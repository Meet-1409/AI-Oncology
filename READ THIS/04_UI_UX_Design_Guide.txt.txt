04_UI_UX_Design_Guide.txt

Project Name

AI Oncology Patient Intelligence Platform

Document Purpose

This document defines the complete visual identity, spatial system, motion language and user experience of the platform. Every screen, component, interaction, animation and transition must follow this document.

This document is the single source of truth for the Spatial Model, the Motion Language, the 3D Rules and the Canonical Vocabulary. Every other document refers back to this one.

The application is not a dashboard. It is a continuous environment the user moves through.

--------------------------------------------------

1. Design Philosophy

The application should feel like an experience, not a website.

Users move through a digital environment rather than opening different pages.

Navigation should feel continuous.

Transitions should feel like camera movement.

Motion should explain where the user is.

The interface should explain itself.

The design should prioritize understanding over navigation.

Every screen answers one question: "What is the next thing this user needs?"

If an element does not help answer that question, reconsider whether it belongs.

The application should never look like:

Traditional healthcare dashboards

Admin panels

Generic EMR software

SaaS templates

Sidebar-driven enterprise software

AI generated interfaces

Low-code generated interfaces

Student projects

Prototypes

4. The Spatial Model

The application has four depth levels. Depth communicates hierarchy. The user always knows their depth.

Depth 0 - Entry

The cinematic introduction and authentication.

Depth 1 - Home Space

The user's orientation surface after authentication.

Depth 2 - Patient Space

Everything belonging to one Patient Case. The Body sits at the centre.

Depth 3 - Focus

A single report, event, task, note or organ. Focus opens in place, layered above the current space. Focus never replaces the space behind it.

Rules

Moving deeper zooms in.

Moving back zooms out.

The space behind remains visible and recognisable at every depth.

The user must never lose context.

Depth must never exceed four levels.

--------------------------------------------------

5. Navigation

Navigation is spatial. The user moves through the environment rather than switching between unrelated pages.

Navigation primitives

Spatial Zoom

Moving into an object rather than selecting a menu item. The object selected becomes the space entered.

Body as Navigation

The Body is a primary navigation space. Selecting an organ reveals the Evidence, Journey events and Understanding related to that organ.

Journey Scrubber

A continuous time control. Moving through time moves the entire space through time, not one isolated panel.

Intent Bar

A single always-available input for expressing intent, including patient search. It replaces menus and removes the need to remember where features are located.

Contextual Orbit

Between four and six contextual destinations arranged around the focal object, revealed on demand. It is not a permanent sidebar.

Continuous Return

A single consistent gesture and control always returns the user to the parent space.

Navigation rules

No permanent sidebar containing dozens of links.

No nested menus.

No admin-panel navigation.

Every important piece of information is reachable within three interactions.

Most information is reachable within one or two interactions.

The current depth and the current Patient Case must always be identifiable.

Users must never be required to remember where a feature is located.

6. Motion Language

Animation is a primary interface element, not decoration.

Animation must

Guide navigation.

Explain hierarchy.

Communicate depth and direction.

Connect different parts of the application.

Direct attention to what changed.

Animation must never

Exist for decoration.

Delay the user.

Obscure clinical information.

Cause motion discomfort.

Motion rules

Transitions are spatial. Entering uses zoom-in. Leaving uses zoom-out.

Shared element continuity is required. The element selected transforms into the space entered.

Motion communicates one of: depth change, time change, clinical change, or processing state.

Typical duration is 180ms to 420ms.

Easing is calm and confident. No bouncing. No elastic motion.

Sudden page changes must be avoided.

Reduced motion

Respecting the operating system reduced motion setting is mandatory.

When reduced motion is enabled, spatial transitions become immediate cross-fades.

All functionality remains identical. No information is lost.

--------------------------------------------------

7. Three-Dimensional Design

3D is part of the product identity and is not limited to the Body.

Use depth, lighting, perspective and layering wherever they aid understanding.

The interface should feel physically layered rather than visually flat.

3D rules

3D must be meaningful. Decorative 3D is not permitted.

3D is required where spatial understanding aids clinical understanding: disease location, disease severity, disease progression, anatomy.

Elsewhere, depth is expressed through layering, shadow, parallax and perspective rather than full 3D scenes.

Text must never be rendered in perspective where it reduces legibility.

Every 3D view must have an equivalent non-3D representation for accessibility and low-capability devices.

Camera movement must never change medical information.

--------------------------------------------------

8. Typography

Use one font family throughout the application.

Hierarchy is created through size, weight and space rather than boxes and borders.

Body text must remain highly readable.

Avoid large paragraphs.

Maintain consistent spacing.

Typography leads the interface. Chrome recedes.

--------------------------------------------------

9. Color Guidelines

Neutral colors dominate the interface.

Primary colors represent trust and professionalism.

Accent colors highlight only important actions.

Error messages use red.

Warnings use amber.

Success messages use green.

Information messages use blue.

Disease visualization uses shades of red. Lighter shades represent lower severity. Darker shades represent higher severity.

Disease severity color must never be the only indicator. A text label always accompanies it.

--------------------------------------------------

10. Surfaces and Layout

The interface uses continuous surfaces rather than grids of boxes.

Avoid layouts filled with boards and cards.

Discrete panels are permitted only when comparing discrete items, such as side by side clinical dates or a list of reports.

Information appears where the user is looking, in context, rather than in a distant panel.

Content is revealed progressively. Detail appears on approach.

Negative space is a design element and must be preserved.

--------------------------------------------------

11. Buttons and Controls

Controls clearly indicate their purpose.

Primary controls represent the main action.

Secondary controls represent optional actions.

Danger controls are used only for destructive actions.

Controls provide hover, focus and active feedback.

Controls appear in context, near the object they act upon.

--------------------------------------------------

12. Forms

Every input has a label.

Validation messages are clear.

Required fields are obvious.

Error messages explain how to fix the issue.

Forms remain short and appear in place rather than on a separate page.

--------------------------------------------------

13. Lists and Tabular Information

Lists support sorting, filtering, searching and pagination.

Long text must never break the layout.

Tabular presentation is used only where comparison across rows genuinely aids understanding.

Where a list represents objects that exist in space, entering an item uses spatial zoom.

--------------------------------------------------

14. Entry (Landing Page)

The Entry is a cinematic introduction to the system, not a traditional landing page.

The first screen must immediately communicate product identity, quality and trust.

It must create curiosity.

It must be memorable.

It must feel premium.

The Entry contains the approved public information: About, Features, How It Works, Contact and access to authentication.

The Entry must remain fast, accessible and usable without 3D.

No patient information is ever accessible from the Entry without authentication.

--------------------------------------------------

15. Home Space (Dashboard)

The Home Space is an orientation surface, not a dashboard of widgets.

It answers one question: what does this user need next.

Patient Home Space presents assigned Actions, recent Evidence, recent Guidance, a Journey preview and Signals.

Practice Space presents assigned patients, recent activity, pending Evidence, Signals and the Intent Bar.

Information is presented in priority order as a continuous surface, not as a grid of boards.

Entering any item uses spatial zoom into the relevant space.

--------------------------------------------------

16. Patient Space (Patient Profile)

Patient Space contains everything belonging to one Patient Case.

The Body sits at the centre of Patient Space.

Journey, Evidence, Understanding, Actions and Guidance are contextual destinations reached from the Body through the Contextual Orbit.

Moving between patients is a lateral spatial movement and must feel smooth and continuous.

Patient identity must remain visible at all times inside Patient Space.

--------------------------------------------------

17. Body (Digital Twin)

The Body is the centrepiece of the application and a primary navigation space.

It must feel like a premium medical visualization tool.

The Body supports rotation, zoom, pan, camera reset and full screen.

The Body integrates directly with Evidence, Journey and Understanding.

Selecting an organ reveals the clinical information and supporting evidence for that organ.

Moving through the Journey updates the Body continuously.

Historical comparison opens smoothly and presents previous and current states together.

The visualization must always remain responsive.

The interface around the Body must never distract from it.

--------------------------------------------------

18. Journey (Timeline)

The Journey is a continuous path through time, not a list of rows.

Clinical events appear in chronological order.

Every event displays date, type, title and summary.

The Journey is also a control. Moving through it moves the entire Patient Space through time.

Selecting an event opens it in Focus without leaving Patient Space.

--------------------------------------------------

19. Evidence (Reports)

Evidence is easy to browse and always traceable to the original document.

Supports search, filter, sort, preview, comparison and version history.

Report status is always visible.

Opening a report uses Focus. The original report remains the source of truth.

--------------------------------------------------

20. Signals (Notifications)

Signals are short, clearly categorized and dismissible.

Signals arrive without interrupting clinical work.

Selecting a Signal moves the user directly to the relevant space.

--------------------------------------------------

21. Loading States

Every space displays loading feedback.

Large content loads progressively.

A blank screen must never be displayed during loading.

Loading uses the motion language. It communicates that the system is moving, not that it is stuck.

The structure of a space appears before its detail.

--------------------------------------------------

22. Empty States

Every empty space explains why it is empty.

Examples

No reports uploaded.

No assigned tasks.

No notifications.

No notes.

No visualization available.

Provide the next possible action whenever appropriate.

--------------------------------------------------

23. Error States

Every error explains the problem.

Every error explains what the user can do next.

Errors avoid technical language.

Errors allow recovery whenever possible.

An error in one space must never break the surrounding environment.

--------------------------------------------------

24. Responsive Design

Desktop is the primary platform.

Tablet remains fully functional.

Mobile supports patient workflows.

The spatial model is preserved across sizes. Depth and continuity do not change.

The Contextual Orbit adapts to available space without becoming a nested menu.

3D scenes reduce complexity on smaller and lower-capability devices while preserving clinical meaning.

--------------------------------------------------

25. Accessibility

Maintain proper color contrast.

Support full keyboard navigation. Every spatial action has a keyboard equivalent.

Use readable font sizes.

Maintain proper spacing.

Do not rely only on color to communicate information.

Respect reduced motion.

Provide non-3D equivalents for all 3D content.

Provide descriptive labels for every interactive element.

Screen reader users must be able to reach every piece of information available to sighted users.

--------------------------------------------------

26. Performance

The environment must remain smooth during navigation.

Target 60 frames per second for all motion and 3D interaction.

Large reports must never block the interface.

The Body must remain responsive during interaction, time changes and comparison.

Assets load progressively so the user is never blocked.

Where the device cannot sustain the target, complexity reduces automatically. Clinical meaning is never reduced.

--------------------------------------------------

27. Consistency

Every space uses the same spacing, typography, controls, forms, motion, depth behaviour, icons and interaction patterns.

The same action produces the same motion everywhere in the application.

Depth always means the same thing.

--------------------------------------------------

28. Final Design Rules

Every interface should feel intentional.

Every interaction should have a purpose.

Every animation should have meaning.

Every space should be understandable without training.

The application should look like software built years ahead of existing healthcare software while remaining practical for daily clinical use.

The platform must create confidence and trust for both patients and oncologists.

Usability is never sacrificed for visual effect.
