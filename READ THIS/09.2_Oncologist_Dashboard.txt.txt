09.2_Oncologist_Dashboard.txt

Project Name

AI Oncology Patient Intelligence Platform

Feature Name

Practice Space (Oncologist Dashboard)

Document Purpose

This document defines the Practice Space. It explains what the oncologist sees immediately after signing in, the available actions, and the expected behaviour of every component.

--------------------------------------------------

1. Purpose

Practice Space is the oncologist's arrival point in the environment, at Depth 1.

Its purpose is to provide an immediate overview of assigned patients, recent activity, pending tasks, uploaded reports and notifications.

It is not an administrative dashboard. It is a calm surface that answers one question: which patient needs this oncologist next.

The oncologist must reach any patient within a few interactions and must never have to search through menus.

--------------------------------------------------

2. Target User

Oncologist

--------------------------------------------------

3. Objectives

Provide an overview of assigned patients.

Display recent patient activity.

Display pending tasks.

Display recently uploaded reports.

Display notifications.

Provide quick access to patient records.

Provide quick access to Patient Intelligence.

--------------------------------------------------

4. Contextual Destinations

Reachable from Practice Space through spatial movement, without a sidebar and without nested menus:

Patient List

Signals (Notifications)

Account (Profile and Settings)

Entering a patient descends into Patient Space at Depth 2, where the Body, Journey, Evidence, Understanding, Actions and Guidance become available.

--------------------------------------------------

5. Spatial Composition

Practice Space is presented as a single continuous surface, in priority order:

Orientation

Practice Summary

Patients requiring attention

Recent Evidence

Pending Actions

Signals

The Intent Bar is always available and does not occupy permanent layout space.

Patients are presented as a set of identifiable presences rather than as rows in an administrative table. Each carries enough clinical context to be recognized without opening it.

--------------------------------------------------

6. Orientation

Display:

Doctor Name

Current Date

Assigned Patient Count

--------------------------------------------------

7. Practice Summary

Display:

Total Assigned Patients

Pending Tasks

New Report Uploads

Unread Notifications

These are presented as a single continuous summary rather than as separate boxes.

--------------------------------------------------

8. Patient Presence (Patient List Preview)

Display recently accessed patients.

Each patient should display:

Patient Name

Patient ID

Cancer Type

Last Visit

Current Status

Open Patient

Selecting a patient zooms into Patient Space. The selected patient becomes the space entered.

--------------------------------------------------

9. Recent Evidence (Recent Report Uploads)

Display recently uploaded reports.

Each report should display:

Patient Name

Report Type

Upload Date

Processing Status

Open Report

--------------------------------------------------

10. Pending Actions (Pending Tasks)

Display tasks assigned to patients.

Each task should display:

Patient Name

Task Title

Assigned Date

Current Status

Review Task

--------------------------------------------------

11. Signals (Notifications)

Display:

New Report Upload

Task Completed

AI Processing Completed

System Notifications

Signals never interrupt clinical work. Selecting a Signal moves the oncologist directly into the relevant space.

--------------------------------------------------

12. Intent Bar (Quick Search)

Allow the oncologist to search patients.

Search by:

Patient Name

Patient ID

Mobile Number

Search results open Patient Space directly.

The Intent Bar is always available and replaces menu-based navigation.

--------------------------------------------------

13. Quick Actions

Provide direct movement to:

Open Patient

Assign Task

View Reports

View Timeline

Open Patient Intelligence

Open Digital Twin

These appear in context rather than as a permanent toolbar.

--------------------------------------------------

14. Motion

Arrival into Practice Space is a descent from the Entry.

Entering a patient uses spatial zoom, with the patient transforming into Patient Space.

Moving from one patient to another is a lateral movement and remains continuous.

New activity is revealed with motion that draws attention to the change.

Reduced motion replaces spatial transitions with immediate cross-fades without any loss of information.

--------------------------------------------------

15. Empty States

No Assigned Patients

Display informative message.

No Recent Uploads

Display informative message.

No Pending Tasks

Display informative message.

No Notifications

Display informative message.

--------------------------------------------------

16. Error States

Network Error

Session Expired

Permission Denied

Server Error

Display clear recovery instructions. An error never breaks the surrounding space.

--------------------------------------------------

17. User Actions

Open Patient

Search Patient

Review Reports

Review Timeline

Review Patient Intelligence

Review Digital Twin

Assign Tasks

Write Patient Notes

Write Private Clinical Notes

View Notifications

Edit Profile

Open Settings

Logout

--------------------------------------------------

18. Business Rules

An oncologist can only access assigned patients.

Patient information is read-only except where updates are allowed.

Tasks can only be assigned by the oncologist.

Private Clinical Notes are visible only to the oncologist.

Patient Notes are visible to both the oncologist and the patient.

The space must never expose another oncologist's patients.

--------------------------------------------------

19. Performance Requirements

The space should load quickly.

Patient search should return results efficiently.

Recent activities should update automatically after refresh.

Large patient lists should support pagination.

The structure of the space appears before its detail. A blank screen is never displayed.

--------------------------------------------------

20. Accessibility

Support keyboard navigation. Every spatial action has a keyboard equivalent.

Maintain readable typography.

Maintain proper spacing.

Provide descriptive labels for every interactive element.

Respect reduced motion.

--------------------------------------------------

21. Completion Criteria

Practice Space is complete when:

Assigned patients are displayed.

Patient search functions correctly.

Recent report uploads are displayed.

Pending tasks are displayed.

Notifications are displayed.

Quick actions function correctly.

Navigation follows the approved spatial model.

The space is ready for backend integration.
