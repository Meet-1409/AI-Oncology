09.8_Tasks.txt

Project Name

AI Oncology Patient Intelligence Platform

Feature Name

Actions (Tasks)

Document Purpose

This document defines the Task Management module. The module allows oncologists to assign tasks to patients and allows patients to complete those tasks. Every task becomes part of the patient's journey and remains linked to the Patient Case.

--------------------------------------------------

1. Purpose

Actions help the oncologist request additional information or follow-up from the patient.

They provide a simple workflow for assigning, tracking and completing patient tasks.

For the patient, Actions are the clearest answer to the question: what do I need to do next.

--------------------------------------------------

2. Target Users

Patient

Oncologist

--------------------------------------------------

3. Objectives

Allow oncologists to assign tasks.

Allow patients to view assigned tasks.

Allow patients to complete tasks.

Allow oncologists to review completed tasks.

Maintain complete task history.

--------------------------------------------------

4. Task Workflow

Oncologist creates task.

↓

Task assigned to patient.

↓

Patient receives a Signal.

↓

Patient views task.

↓

Patient completes task.

↓

Task submitted.

↓

Oncologist reviews submission.

↓

Task marked completed.

--------------------------------------------------

5. Spatial Composition

For the patient, Actions appear first in Patient Home Space, closest to the viewer, because they are the most urgent thing the patient needs.

For the oncologist, Actions are reached from the Contextual Orbit in Patient Space, and pending Actions across all patients are visible from Practice Space.

Creating, reviewing and completing an Action all happen in place, in Focus above the current space. Neither user leaves their space to work with an Action.

Actions are presented as a short prioritized sequence, not as a board of cards.

--------------------------------------------------

--------------------------------------------------

8. Task Status

Every task should display its current status.

Available statuses:

Pending

In Progress

Completed

Cancelled

Status must never be communicated by color alone.

--------------------------------------------------

9. Patient View

Patients should be able to:

View assigned tasks.

Read task instructions.

Upload requested documents.

Track task status.

View completed tasks.

Patients cannot edit assigned tasks.

Patients cannot delete assigned tasks.

Instructions are written in simple language. The patient must never feel overwhelmed.

--------------------------------------------------

10. Oncologist View

Oncologists should be able to:

Create tasks.

Assign tasks.

View task status.

Review completed tasks.

Cancel tasks.

Create custom tasks.

--------------------------------------------------

11. Task Details

Opening a task should display:

Task Title

Instructions

Assigned Date

Due Date

Priority

Current Status

Uploaded Files

Completion History

--------------------------------------------------

12. File Upload

If a task requires report submission, the patient should be able to:

Upload files.

Replace failed uploads.

View upload progress.

Receive upload confirmation.

Uploading happens in place within the task. The patient never leaves their space.

--------------------------------------------------

Support sorting by:

Status

--------------------------------------------------

16. Notifications

Patients should receive notifications when:

A new task is assigned.

A task is updated.

A task is cancelled.

A task is reviewed.

Oncologists should receive notifications when:

A patient completes a task.

A patient uploads requested files.

--------------------------------------------------

17. Timeline Integration

Every task should automatically appear in the patient's Journey.

Timeline events should include:

Task Assigned

Task Updated

Task Completed

--------------------------------------------------

18. Motion

Opening a task lifts it into Focus above the current space.

Completing a task is confirmed with motion that communicates the change of state, and the task settles into its completed position rather than disappearing abruptly.

Newly assigned tasks are revealed with motion that draws attention.

Reduced motion replaces these transitions with immediate cross-fades without any loss of information.

--------------------------------------------------

19. Business Rules

Only oncologists can create tasks.

Only the assigned patient can complete tasks.

Completed tasks cannot be edited.

Cancelled tasks remain in the patient's history.

Every completed task remains permanently linked to the Patient Case.

--------------------------------------------------

20. Empty States

No Tasks Assigned

Display informative message.

No Completed Tasks

Display informative message.

--------------------------------------------------

21. Error States

Task Creation Failed

Task Update Failed

Upload Failed

Network Error

Permission Denied

Display clear recovery instructions. A failed upload allows retry without losing the user's position.

--------------------------------------------------

22. Performance Requirements

Task list should load quickly.

Large task lists should support pagination.

Status updates should appear immediately after refresh.

--------------------------------------------------

23. Accessibility

Support keyboard navigation. Every task action has a keyboard equivalent.

Maintain readable typography.

Provide descriptive labels for every action.

Maintain consistent spacing.

Status and priority must never rely on color alone.

Respect reduced motion.

--------------------------------------------------

24. Completion Criteria

The Actions module is complete when:

Oncologists can create tasks.

Patients can view tasks.

Patients can complete tasks.

Task statuses update correctly.

Notifications function correctly.

Timeline integration functions correctly.

Search functions correctly.

Filtering functions correctly.

Sorting functions correctly.

The module is ready for backend integration.
